VRH.AI

Privacy Policy

Last updated: September 2026

1. Privacy Commitment & Architecture

VRH.AI is an open-source autonomous browser copilot built strictly on a Bring-Your-Own-Key (BYOK) model. All computational operations, settings configurations, and chat histories reside entirely within your local browser environment. We do not operate an intermediary server, telemetry service, tracking beacon, or user database.

2. Data Collection and Transmission

VRH.AI does not collect, harvest, store, or sell personal information:

  • Zero Telemetry / Analytics: We collect zero analytics, zero usage tracking metrics, and zero behavioral telemetry. We do not use tracking cookies or external logging endpoints.
  • Direct Provider Communications: Chat prompts, attached images, and document context are transmitted directly from your client browser to your chosen AI model provider (e.g., OpenRouter, Groq, Ollama, or a custom OpenAI-compatible endpoint) using your personal API key.
  • Client-Side Processing: Webpage extraction and contextual assembly occur entirely within your Chromium browser sandbox solely upon your explicit instruction.

3. Screen & Tab Capture Disclosure (Vision Mode & Manual Attachment)

VRH.AI uses the chrome.tabs.captureVisibleTab API to capture viewport screenshots under two strictly defined user actions:

  • Manual Attachment: When you explicitly click the "Capture Tab Screenshot" button in the side panel, the active tab's visible area is captured as a PNG and displayed in your input staging area. It is transmitted to your configured AI provider only when you press submit.
  • Autonomous Agent Mode: When you activate Autonomous Agent Mode with a vision-capable AI model selected, the extension captures a JPEG screenshot of the target tab at each reasoning step to apply Set-of-Mark visual grounding labels. This annotated image is sent directly to your configured multimodal LLM endpoint to enable visual element selection.
  • Local In-Memory Lifetime: Older step screenshots are pruned from memory immediately during execution. Screenshots are never saved to disk, never cached permanently, and never transmitted to any third party other than your explicitly chosen AI provider endpoint.

4. On-Device Local OCR Processing (Tesseract.js)

For PDF documents that lack an embedded text layer (such as scanned physical papers or image-only PDFs), VRH.AI performs Optical Character Recognition (OCR) using a fully vendored, client-side Tesseract.js engine:

  • 100% On-Device Execution: All OCR analysis executes entirely on your device inside the local browser WebAssembly (WASM) runtime.
  • Zero Network Transmission: The OCR worker, WASM binaries, and trained language model data (eng.traineddata.gz) are bundled within the extension itself under extension/lib/tesseract/. No document, image slice, or text string is sent across the network for OCR parsing.

5. Chrome DevTools Protocol (CDP) & Debugger Permission Disclosure

VRH.AI requests the debugger permission to enable hardware-level browser automation via the Chrome DevTools Protocol (CDP):

  • Purpose of Debugger: During active Autonomous Agent Mode execution, the extension uses CDP (chrome.debugger) to dispatch genuine, trusted hardware input events—including mouse clicks, scrolling, and keyboard typing—enabling automation across modern single-page applications and complex web interfaces.
  • What CDP Observes: While attached, CDP monitors navigation events, network idle status, and native JavaScript dialogs to confirm that an action (such as clicking a link or submitting a form) has concluded before proceeding to the next step.
  • Ephemeral Attachment: The debugger attaches only to the target tab during active agent task execution and detaches immediately when the task is finished, canceled, or stopped.
  • Sensitive Action Gate: The agent is governed by an automated Sensitive Action Gate that detects transactional or irreversible actions (such as checkout buttons, payment forms, account deletions, or password submissions), pausing execution and requiring explicit human user approval before any sensitive input is dispatched.

6. Local Storage Sandbox

All user preferences, provider credentials, model selections, custom prompts, domain blacklists, and conversation histories are stored exclusively in Chrome's isolated storage sandbox (chrome.storage.local). This data is sandboxed to the extension and is inaccessible to web pages or third-party extensions.

7. Third-Party AI Providers

When you provide an API key for OpenRouter, Groq, Ollama, or custom endpoints, your prompt data and any attached images/tab context are sent directly to that provider. Data handling, logging, and retention policies are governed by the terms and privacy policy of your chosen AI provider.

8. User Control and Data Authority

You have complete control over your data. You may clear your conversation history, revoke API keys, export configurations, or wipe all extension data at any time through the VRH.AI Settings page or by uninstalling the extension.
